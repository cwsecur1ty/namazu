Baseline for this operation generated

An audit can only test what its first request reached. Where the contract documents no example, the generated request carries the literal string, which usually names nothing that exists, and every probe that compares against it then has nothing to compare.

Paste a URL you know works for the selected operation. Use From last run to take the one the Request tab just sent.

Credential headers in a saved example are ignored. The identity being audited is always applied over it, so an example cannot change who the audit runs as.

A 2xx is not always success, and an expected negative test may legitimately return 403. Tick the box for an operation this identity is supposed to be refused, and a refusal becomes a baseline that worked rather than a reported gap.

A resource marker is what distinguishes "the caller got this object" from "the caller got an object of this shape". Status codes and body similarity cannot tell those apart.

Second opinion not checked

Runs an external scanner against the same target and folds what it reports into this findings list, tagged with the tool that found it. Namazu does not re-verify those matches, and says so on each one.

Run audit then runs each available tool in turn, once Namazu's own checks have finished, and folds what they report into the same list.

Both are run read-only: destructive and brute-force templates are excluded, nuclei runs without its callback service, and schemathesis is held to safe methods unless Allow writes is on. nuclei includes CVE templates, so expect minutes rather than seconds.
